# Day 06
- Prompt: `ai_testgen/prompts/scenario_generation.md`, filled with a story and its acceptance criteria. Stories live in `ai_testgen/stories/`; outputs from `uv run python -m scripts.gen_scenarios` are saved in `ai_testgen/outputs/` (committed as evidence).
- **v1 prompt problems (llama3.1:8b):** the model added a "Here are the test scenarios:" preamble, wrapped headers in markdown bold, invented expected error text ("Invalid amount. Please enter a positive number."), invented account ids ("12345"), and invented UI behaviour ("Pay Bill button is disabled"). My own counter reported 0 scenarios for 5 of 6 runs because of the bold. Lesson: check the parser against real output before blaming the model.
- **v2 prompt:** forbids markdown and preamble, says to quote messages only when the criteria give them, and not to invent data. Result: clean plain-text blocks, 3-5 scenarios per run, no invented messages. The counter now tolerates markdown anyway.
- **T=0 vs T=0.8:** both cover happy, negative and (mostly) edge cases. T=0 gave a steady 4 scenarios per story; T=0.8 varied (3-5) and produced different titles and extra ideas (insufficient balance, minimum amount, no funding account), but also dropped the edge case for open account and used inconsistent casing ("Happy" vs "happy"). T=0 is better for repeatable pipelines; T=0.8 is useful once to widen coverage.
- **Remaining defects at T=0:** it wrote `an error message is shown with the text "Transfer Complete!"` (mixed up the success message), made up a "Same Account Selected" rule that is not in the criteria, and one scenario only checks the page layout, not a behaviour. The model does not know ParaBank's real behaviour, so generated expectations must be reviewed. This is why Day 7 adds a schema and Day 9 grounds generation in the real page.
- Free text is hard to consume programmatically (casing, headers differ); Day 7 moves to structured JSON.
