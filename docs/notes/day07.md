# Day 07
- `ai_testgen/schema.py`: Pydantic `TestCase` (title, type, priority, preconditions, steps, expected) and `TestCaseList`. Enums are lower-cased by a validator because models return "Happy"/"HIGH"; `steps` must be non-empty.
- `ai_testgen/parser.py`: strips code fences, tolerates chatter around the JSON, accepts a bare list or `{"test_cases": [...]}`, and raises `ParseError` with a message that is safe to show the model.
- `ai_testgen/structured.py`: calls the LLM with Ollama's JSON mode (`format="json"`), validates, and on failure **re-prompts with the validation error** (max 2 retries). A blind retry at temperature 0 would just return the same bad output, so feeding the error back is what makes retry useful.
- Tests use a scripted fake client with canned responses: invalid JSON, schema violations, fences, chatter, retry count, give-up behaviour (24 tests across parser/structured/scenarios, no Ollama needed).
- Live result with llama3.1:8b at T=0: all 3 stories produced valid JSON on the first attempt, in two separate runs (0 retries needed). JSON mode plus a clear shape in the prompt is doing most of the work; retry is insurance, not the main path.
- Content is still imperfect: for transfer funds the model proposed "account not owned by the customer" (impossible through the UI, which only lists own accounts) and a muddled "same account" edge case. Valid JSON does not mean a good test. Human review and grounding in the real page (Day 9) are still needed.
- **Why structured output beats free text:** Day 6 free text needed a fragile counter and could not be consumed by code (casing, markdown, preambles varied). A schema gives validation, defaults, machine-readable fields (priority/type for filtering and scheduling), and a place to reject bad output automatically before it reaches a code generator on Day 8.
